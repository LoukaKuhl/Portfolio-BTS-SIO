Contexte et rôle

Pendant mon stage chez Agence418, mon tuteur m’a laissé choisir le projet que je souhaitais réaliser. J’ai décidé de créer CodeGrimoire de toutes pièces afin de me former au développement full-stack et de réaliser une application complète pendant toute la durée du stage.

D’après le rapport de stage, CodeGrimoire est une application web privée de gestion, de stockage et de recherche de snippets de code. Le projet comprend la mise en place de l’environnement de développement, la conception de maquettes et de la base de données, le développement du front-end, la création de l’API REST, la connexion à Supabase, les tests, la sécurisation et le déploiement.

Difficultés rencontrées et solutions

  • Correction d’une variable d’environnement Supabase mal nommée.
  • Résolution d’une incompatibilité WebSocket avec Node.js 20 grâce à l’installation et la configuration du paquet adapté.
  • Suppression d’un import circulaire entre le serveur et les routes grâce à la séparation de la connexion Supabase.
  • Correction d’un identifiant conservé dans le DOM après suppression d’un snippet, qui provoquait une tentative de modification sur un élément inexistant.
  • Prise en compte de la sécurité : protection contre les injections XSS, activation du RLS Supabase et sécurisation de l’API.

Résultat obtenu

Le résultat est une application web fonctionnelle de gestion de snippets de code, avec une interface, une API REST, une base de données Supabase, une recherche en temps réel, des opérations CRUD, un bouton de copie et un déploiement composé d’un backend Docker et d’un frontend hébergé sur Render.

Détails du TPTP cybersécurité

Contexte du TP

Le TP place l’étudiant dans le contexte d’un service de cybersécurité d’une organisation bancaire. L’objectif est de tester la robustesse de mots de passe fictifs à l’aide d’un programme Python, sans utiliser de données réelles.

Travail demandé

  • Créer une base de test SQLiteStudio et la remplir avec des comptes fictifs.
  • Accéder à la base et aux dictionnaires depuis Python.
  • Tester les mots de passe avec un dictionnaire, puis avec des nombres de 0000 à 9999.
  • Combiner un dictionnaire principal avec `complement.txt` et `speciaux.txt`.
  • Créer un menu permettant de choisir les différents tests.
  • Étudier les permutations de dictionnaires et de nombres, puis réaliser une recherche exhaustive sur quatre caractères.

Le TP rappelle également que, dans un contexte professionnel, les mots de passe ne doivent pas être stockés en clair : seules leurs empreintes chiffrées doivent être conservées.

Détails du TPTP Python

Objectif du TP

Le TP étudie la reconstitution d’un numéro de sécurité sociale à partir de données incomplètes, afin de comprendre comment des informations apparemment anodines peuvent contribuer à révéler une donnée confidentielle.

Travail demandé

  • Créer un questionnaire permettant de saisir les informations disponibles.
  • Reconstituer les treize premiers chiffres du numéro.
  • Créer une fonction Python calculant la clé de sécurité à partir des treize premiers chiffres.
  • Afficher les combinaisons viables et non viables dans un second scénario.
  • Créer un menu texte permettant de choisir entre les deux scénarios.

Le TP présente la clé de contrôle comme deux chiffres compris entre 01 et 97 et donne la formule : clé de sécurité = 97 - (numéro de sécurité sociale modulo 97).

Détails du TP base de donnéesTP BDD

Univers étudié

L’univers choisi est Pokémon Kanto, issu des jeux vidéo Pokémon. La base représente les Pokémon, les espèces, les dresseurs, leurs villes d’origine, les attaques, les types, les objets, les badges, les zones géographiques, la météo et les apparitions.

Le rapport précise que les combats détaillés, les évolutions complexes, les échanges multijoueur et les variantes d’attaques aux effets spéciaux complexes ont été volontairement ignorés dans la modélisation.

Modélisation et structure

Le modèle a été réalisé avec Looping, puis décrit sous forme de MLD textuel. Il comprend notamment les tables Type_Pokémon, Ville, Zone, Objet, Dresseur, Badge, Espece_Pokémon, Attaque_Pokémon et Pokémon_Individu, ainsi que les tables d’association pour les types, attaques apprises, objets possédés, badges gagnés, apparitions et efficacités.

Scripts SQL et exploitation

  • Création des tables avec clés primaires, clés étrangères et contraintes.
  • Insertion de données fictives concernant les types, villes, zones, objets, dresseurs, badges, espèces, attaques et Pokémon individuels.
  • Exploitation de la base à l’aide de questions métier et de requêtes SQL.
  • Classement des requêtes par difficulté : facile, intermédiaire et difficile.

Le rapport contient les scripts de création et d’insertion ainsi que les requêtes SQL testées, avec des exemples de jointures, filtres, tris, agrégations et relations entre les différentes tables.

Livrables du projet

Le rendu comprend la présentation de l’univers, les captures du modèle Looping, le MLD textuel, le script de création de la base, les scripts d’insertion, la sauvegarde de la base de données et les fichiers annexes utilisés pour réaliser le TP.

La veille technologique consiste à surveiller régulièrement les nouveautés, les évolutions techniques et l'émergence de nouveaux outils afin de maintenir mes compétences à jour et de proposer des architectures logicielles modernes et sécurisées.

Méthodologie & Outils de collecte

Pour structurer ma veille de manière efficace, j'utilise un écosystème d'outils professionnels :

Sujet de ma veille

Thématique principale : L'écosystème JavaScript Moderne (Back-end & Cloud) et les architectures d'applications décentralisées

Ma veille s'articule autour de deux axes stratégiques liés à mes projets de stage :

Thème 1 : Évolutions de Node.js et du Back-end TypeScript

  • TypeScript : Suivi des mises à jour du langage pour sécuriser le typage des API (Dev.to / TypeScript Blog).
  • Frameworks & APIs : Évolution des performances d'Express et alternatives émergentes (Fastify, NestJS).
  • Bases de données BaaS : L'essor de Supabase et l'intégration des politiques de sécurité de niveau ligne (RLS) avec PostgreSQL.

Thème 2 : Performance Web, PWA et Conteneurisation

  • Progressive Web Apps (PWA) : Nouvelles API des navigateurs pour la gestion avancée du cache et des Services Workers en mode déconnecté.
  • Conteneurisation (Docker) : Bonnes pratiques d'écriture de Dockerfiles légers (Multi-stage builds) pour optimiser le déploiement.
  • PaaS / Déploiement : Évolution des services de Cloud modernes comme Render et Vercel face aux hébergements traditionnels.
